# Raw 03：為什麼驗證最花時間？功能驗證與靜態時序分析
- **來源**：OFweek 電子工程網 — https://ee.ofweek.com/2021-03/ART-11000-2801-30488728.html
- **主題**：功能驗證、Testbench、覆蓋率、形式驗證、STA

## 核心內容
1. **驗證佔據 50%～70% 的開發時間**：
   - 軟體有 Bug 可以發佈更新檔（Patch）修補，但晶片一旦送去晶圓廠製造（Tape-out），光罩費用動輒數百萬至數千萬美元，發現硬體 Bug 幾乎無法事後修補，只能重做。
   - 因此在業界，驗證工程師與設計工程師的人數比例經常高達 **2:1 甚至 3:1**。

2. **功能驗證（Functional Verification）怎麼做？**：
   - 工程師會建立一個虛擬測試環境，稱為 **Testbench（測試平台）**，對 RTL 電路輸入各種正常與極端的測試訊號，進行模擬（Simulation），比對輸出結果是否與預期一致。
   - 為了確保沒有漏測的角落，會使用 **覆蓋率（Coverage）** 指標來衡量「程式碼與各種情境到底測了多少比例」。
   - 此外還會搭配 **形式驗證（Formal Verification / Equivalence Checking）**，用數學方法證明「合成後的 Netlist」與「原本的 RTL」在邏輯功能上完全等價。

3. **靜態時序分析（STA, Static Timing Analysis）**：
   - 功能算對了還不夠，訊號還必須「準時到達」。STA 會檢查晶片中每一條訊號路徑的延遲時間，確保資料在時脈（Clock）切換前已經穩定準備好（滿足 Setup Time 與 Hold Time），避免晶片跑太快時發生資料錯亂。
